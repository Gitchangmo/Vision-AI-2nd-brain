# 2nd Brain Template

> 흩어진 생각과 정보를 한곳에 모으고, 서로 연결해 실제 행동으로 이어 가기 위한 Markdown 기반 지식 관리 템플릿입니다.

이 프로젝트는 메모를 단순히 보관하는 데서 끝내지 않고 **수집 → 정리 → 연결 → 실행 → 회고**의 흐름으로 운영하는 것을 목표로 합니다. 모든 노트는 일반 Markdown 파일로 관리하므로 특정 앱에 종속되지 않으며, Obsidian·VS Code·GitHub 등 원하는 도구에서 사용할 수 있습니다.

## 핵심 원칙

- **빠르게 수집하기**: 정리 방법을 고민하기 전에 `00 Inbox`에 먼저 기록합니다.
- **행동과 연결하기**: 실행 가능한 정보는 프로젝트와 할 일로 연결합니다.
- **맥락으로 분류하기**: PARA 방식으로 프로젝트, 책임 영역, 참고 자료, 보관 자료를 구분합니다.
- **작게 나누고 연결하기**: 하나의 노트에는 하나의 핵심 아이디어를 담고 관련 노트를 링크합니다.
- **주기적으로 비우기**: Inbox와 완료된 프로젝트를 정기적으로 검토합니다.

## 권장 폴더 구조

```text
.
├── 00 Inbox/         # 아직 분류하지 않은 메모와 아이디어
├── 01 Daily/         # 일일 기록, 회고, 임시 작업 노트
├── 10 Projects/      # 명확한 목표와 완료 시점이 있는 작업
├── 20 Areas/         # 지속적으로 관리해야 하는 책임 영역
├── 30 Resources/     # 관심 주제별 참고 자료와 지식
├── 40 Archive/       # 완료되었거나 더 이상 사용하지 않는 자료
├── 90 Templates/     # 반복해서 사용하는 노트 양식
└── 99 Attachments/   # 이미지, PDF 등 첨부 파일
```

폴더는 처음부터 모두 만들 필요가 없습니다. 실제로 필요한 시점에 추가하고, 분류가 애매한 내용은 우선 `00 Inbox`에 보관하세요.

## 빠르게 시작하기

### 1. 저장소 복제

```bash
git clone git@github.com:ains-lab/2nd-brain-template.git
cd 2nd-brain-template
```

### 2. 기본 폴더 생성

```bash
mkdir -p "00 Inbox" "01 Daily" "10 Projects" "20 Areas" \
  "30 Resources" "40 Archive" "90 Templates" "99 Attachments"
```

### 3. 원하는 Markdown 편집기에서 열기

- **Obsidian**: `Open folder as vault`를 선택한 뒤 저장소 폴더를 지정합니다.
- **VS Code**: 저장소에서 `code .`을 실행합니다.
- **기타 편집기**: Markdown 파일과 폴더를 편집할 수 있는 도구라면 무엇이든 사용할 수 있습니다.

## 기본 사용 흐름

1. **수집**: 떠오른 생각, 링크, 회의 메모를 `00 Inbox`에 바로 기록합니다.
2. **정리**: 매일 또는 매주 Inbox를 검토해 적절한 폴더로 이동합니다.
3. **연결**: 관련 프로젝트와 주제 노트를 링크하고 다음 행동을 적습니다.
4. **실행**: 현재 진행 중인 프로젝트 노트를 중심으로 할 일을 처리합니다.
5. **회고**: Daily 노트에서 진행 상황과 배운 점을 돌아봅니다.
6. **보관**: 완료된 프로젝트와 더 이상 활성 상태가 아닌 자료는 `40 Archive`로 옮깁니다.

## 노트 작성 규칙

### 파일 이름

검색과 정렬이 쉬운 일관된 이름을 사용합니다.

| 노트 종류 | 권장 형식 | 예시 |
| --- | --- | --- |
| Daily | `YYYY-MM-DD.md` | `2026-07-21.md` |
| 프로젝트 | `프로젝트 이름.md` | `웹사이트 리뉴얼.md` |
| 회의 | `YYYY-MM-DD 회의명.md` | `2026-07-21 주간 회의.md` |
| 자료 | 내용을 설명하는 구체적인 제목 | `효과적인 회고 질문.md` |

### 속성

필요한 노트에는 다음과 같은 YAML 속성을 추가할 수 있습니다.

```yaml
---
title: 노트 제목
created: 2026-07-21
updated: 2026-07-21
tags:
  - topic/example
status: active
---
```

속성은 검색이나 자동화에 실제로 사용할 항목만 유지하세요. 모든 노트에 동일한 메타데이터를 강제할 필요는 없습니다.

### 링크

사용하는 편집기에 따라 일반 Markdown 링크 또는 위키 링크를 사용할 수 있습니다.

```markdown
[프로젝트 계획](../10%20Projects/프로젝트%20계획.md)
[[프로젝트 계획]]
```

공개 저장소나 여러 편집기를 함께 사용할 계획이라면 호환성이 높은 일반 Markdown 링크를 권장합니다.

## 추천 템플릿

### Daily 노트

```markdown
# 2026-07-21

## 오늘의 목표

- [ ] 가장 중요한 일 한 가지

## 기록

- 떠오른 생각과 진행 상황

## 회고

- 잘한 점:
- 개선할 점:
- 내일 이어서 할 일:
```

### 프로젝트 노트

```markdown
# 프로젝트 이름

## 목표

프로젝트가 완료되었다고 판단할 수 있는 결과를 적습니다.

## 다음 행동

- [ ] 지금 바로 실행할 수 있는 구체적인 작업

## 진행 기록

- YYYY-MM-DD: 주요 결정 또는 변경 사항

## 관련 자료

- 관련 노트와 외부 자료 링크
```

## 주간 리뷰

매주 한 번 아래 항목을 확인하면 시스템이 오래 유지됩니다.

- [ ] `00 Inbox`의 메모를 분류하거나 삭제했는가?
- [ ] 진행 중인 프로젝트마다 다음 행동이 정해져 있는가?
- [ ] 완료된 프로젝트를 `40 Archive`로 옮겼는가?
- [ ] 반복해서 참고한 정보가 별도 Resource 노트로 정리되어 있는가?
- [ ] 필요 없어진 태그, 링크, 첨부 파일을 정리했는가?

## 동기화와 백업

Markdown 파일은 Git으로 변경 이력을 관리할 수 있습니다.

```bash
git add .
git commit -m "docs: update second brain notes"
git push
```

민감한 개인정보, 비밀번호, API 키는 저장소에 기록하지 마세요. 여러 기기에서 사용할 경우 Git 외에도 사용하는 편집기의 공식 동기화 기능이나 신뢰할 수 있는 백업 방식을 함께 고려하세요.

## 나에게 맞게 확장하기

이 구조는 시작점일 뿐입니다. 실제 사용 패턴에 따라 다음 항목을 추가하거나 제거할 수 있습니다.

- 독서, 강의, 회의 등 자주 작성하는 노트 템플릿
- 개인·업무 영역을 구분하는 태그 또는 하위 폴더
- 습관, 목표, 지표를 확인하는 대시보드
- 캘린더, 할 일 관리 도구, 자동화 스크립트 연동

가장 좋은 2nd Brain은 기능이 가장 많은 시스템이 아니라, 부담 없이 계속 기록하고 다시 찾을 수 있는 시스템입니다.

## 기여하기

개선 아이디어나 새로운 템플릿은 Issue로 제안하거나 Pull Request로 공유해 주세요. 변경 사항은 특정 도구에만 의존하지 않고 일반 Markdown 환경에서도 이해할 수 있도록 작성하는 것을 권장합니다.
